# Self-Service Storage System - Phase 1 Implementation Notes

## Overview
This document outlines the Phase 1 implementation of a production-ready self-service storage system with proper authentication, authorization, and optimized database queries.

## What Was Implemented (Phase 1)

### 1. Infrastructure (CloudFormation/SAM)

#### Email Configuration (SES)
- Added 3 CloudFormation parameters for email addresses:
  * SenderEmail (noreply@qinisoxulu.com) - General notifications
  * SupportEmail (support@qinisoxulu.com) - Security notifications
  * InvoicesEmail (invoices@qinisoxulu.com) - Invoice emails
- Created SES Configuration Set and 3 Email Identity resources
- All Lambda functions use parameter references for emails

#### DynamoDB Tables
Added 9 DynamoDB tables with Global Secondary Indexes (GSIs):

1. **FacilitiesTable**
   - Primary Key: facility_id
   - GSIs: city-index, status-index

2. **UnitsTable**
   - Primary Key: unit_id
   - GSI: facility-status-index (compound key for efficient availability queries)

3. **RentalsTable**
   - Primary Key: rental_id
   - GSIs: user-index (user_id + status), unit-index, status-index
   - Supports rental_type: 'subscription' | 'one-time'
   - DynamoDB Streams enabled

4. **InvoicesTable**
   - Primary Key: invoice_id
   - GSIs: user-index (user_id + created_at), status-index (status + created_at), rental-index
   - DynamoDB Streams enabled

5. **PaymentMethodsTable**
   - Primary Key: payment_method_id
   - GSI: user-index

6. **ShareRequestsTable**
   - Primary Key: request_id
   - GSI: owner-index (owner_user_id + status)
   - DynamoDB Streams enabled

7. **SharedUnitsTable**
   - Primary Key: share_id
   - GSI: unit-index (unit_id + user_email)

8. **AccessEventsTable**
   - Primary Key: event_id
   - GSI: unit-index (unit_id + timestamp)
   - TTL enabled for automatic cleanup
   - DynamoDB Streams enabled

9. **UsersTable**
   - Primary Key: user_id
   - GSIs: email-index, user_type-index

All tables use:
- PAY_PER_REQUEST billing mode (on-demand)
- Point-in-time recovery enabled

#### Cognito Authentication
- **User Pool** with custom attributes:
  * custom:user_type (admin | client)
  * custom:full_name
- **User Pool Client** configured for SRP authentication
- **User Pool Domain** for hosted UI
- **Post-confirmation trigger** to create user records in DynamoDB
- **API Gateway Cognito Authorizer** for JWT validation

#### Lambda Layer
Created CommonUtilsLayer with shared utilities:
- **auth_utils.py**: Authentication decorators and helpers
  * @require_auth - Extracts user from Cognito claims
  * @require_role() - Role-based access control
  * is_admin() - Check admin privileges
  * owns_resource() - Ownership verification
- **response_utils.py**: Standardized API responses
  * success_response()
  * error_response(), validation_error(), forbidden_error(), etc.
  * DecimalEncoder for DynamoDB Decimal handling

### 2. Lambda Functions Updated

#### Authentication Added (9 functions)
1. **create_rental** (backend/create_rental/app.py)
   - Added @require_auth decorator
   - Extracts user_id from Cognito claims (not request body)
   - Validates payment method belongs to authenticated user
   - Supports rental_type: 'subscription' | 'one-time'
   - Uses DynamoDB transactions for atomic rental creation + unit status update
   - Prevents unauthorized bookings

2. **show_user_rentals** (backend/show_user_rentals/app.py)
   - Added @require_auth decorator
   - Uses user-index GSI (QUERY instead of SCAN)
   - Admin override: admins can query any user via ?user_id parameter
   - Enriches data with unit and facility details

3. **select_invoices** (backend/select_invoices/app.py)
   - Added @require_auth decorator
   - Uses user-index GSI (QUERY instead of SCAN)
   - Optional status filtering

4. **show_payment_methods** (backend/show_payment_methods/app.py)
   - Added @require_auth decorator
   - Uses user-index GSI (QUERY instead of SCAN)
   - Users can only see their own payment methods

5. **upsert_payment_method** (backend/upsert_payment_method/app.py)
   - Added @require_auth decorator
   - Extracts user_id from Cognito claims
   - Prevents users from adding payment methods to other accounts

6. **show_share_requests** (backend/show_share_requests/app.py)
   - Added @require_auth decorator
   - Uses owner-index GSI (QUERY instead of SCAN)
   - Shows requests for authenticated user's units only

7. **approve_share_request** (backend/approve_share_request/app.py)
   - Added @require_auth decorator
   - CRITICAL: Ownership verification - only unit owner can approve/deny
   - Generates unique share_id and creates SharedUnits entry
   - Prevents unauthorized share request manipulation

8. **trigger_on_user_created** (backend/trigger_on_user_created/app.py)
   - Updated to read custom:user_type and custom:full_name from Cognito
   - Stores all user attributes in UsersTable
   - Sends welcome email via SES

9. **trigger_recurring_billing** (backend/trigger_recurring_billing/app.py)
   - Updated to filter rental_type='subscription' only
   - Uses status-index GSI (QUERY instead of SCAN)
   - Added idempotency check (prevents duplicate invoices)

#### Query Optimization (Public Endpoints - No Auth)
1. **show_facility_availability** (backend/show_facility_availability/app.py)
   - Replaced SCAN with QUERY using facility-status-index GSI
   - Efficiently retrieves available units for a facility

### 3. API Gateway Configuration
- **Default Authorizer**: CognitoAuthorizer (all endpoints require JWT by default)
- **Public Endpoints** (Auth: NONE):
  * GET /facilities (show_facilities)
  * GET /facilities/{facility_id}/availability (show_facility_availability)
  * GET /units/{unit_id} (show_unit_details)
  * GET /units/{unit_id}/pricing (show_unit_pricing)
- **Authenticated Endpoints** (require valid JWT):
  * All other endpoints

### 4. Security Improvements
- ✅ NO authentication → Cognito JWT validation
- ✅ Users can spoof user_id → Extract user_id from Cognito claims
- ✅ NO authorization → Ownership verification and role-based access control
- ✅ Anyone can approve share requests → Only unit owner can approve
- ✅ Anyone can view any user's data → User-scoped queries with admin override

### 5. Performance Improvements
- ✅ All SCAN operations → QUERY operations with GSIs
- ✅ N+1 queries → Optimized with batch gets or single queries
- ✅ No indexes → 14 GSIs across 9 tables

## Deployment Steps

### Prerequisites
- AWS CLI configured with appropriate credentials
- AWS SAM CLI installed
- SES verified email identities (noreply@, support@, invoices@ qinisoxulu.com)

### 1. Deploy Infrastructure
```bash
cd backend
sam build
sam deploy --guided
```

During guided deployment:
- Stack Name: capstone-production
- Region: (your preferred region)
- SenderEmail: noreply@qinisoxulu.com
- SupportEmail: support@qinisoxulu.com
- InvoicesEmail: invoices@qinisoxulu.com
- Confirm changes: Y
- Allow SAM CLI IAM role creation: Y
- Disable rollback: N
- Save arguments to samconfig.toml: Y

### 2. Verify Deployment
Check CloudFormation stack status:
```bash
aws cloudformation describe-stacks --stack-name capstone-production
```

Get output values:
```bash
aws cloudformation describe-stacks --stack-name capstone-production --query 'Stacks[0].Outputs'
```

Note the following outputs:
- ApiGatewayUrl
- UserPoolId
- UserPoolClientId
- CognitoDomain

### 3. Verify SES Email Identities
```bash
aws ses list-identities
```

If identities are not verified, check email for verification links.

**Client User:**

```bash
  --client-id <UserPoolClientId> \

  --user-attributes Name=email,Value=client@example.com Name=custom:user_type,Value=client Name=custom:full_name,Value="Client User"

aws cognito-idp admin-confirm-sign-up \
  --user-pool-id <UserPoolId> \

```

### 2. Get JWT Token
```bash
aws cognito-idp initiate-auth \
  --auth-flow USER_PASSWORD_AUTH \
  --client-id <UserPoolClientId> \
  --auth-parameters USERNAME=client@example.com,PASSWORD=TestPassword123! \
  --query 'AuthenticationResult.IdToken' \
  --output text
```

Save the IdToken for API testing.

## Troubleshooting

### Issue: CloudFormation fails with "Table already exists"
**Solution**: Either:
1. Delete existing tables manually
2. Update template.yaml to use different table names
3. Use `sam deploy --no-fail-on-empty-changeset` to skip unchanged resources

### Issue: Cognito trigger not working
**Solution**: Verify:
1. Lambda permission exists (CognitoTriggerPermission resource)
2. Function has correct IAM policies
3. Check CloudWatch Logs for errors

### Issue: 401 Unauthorized on all requests
**Solution**: Check:
1. Cognito User Pool ARN in API Gateway authorizer
2. JWT token is not expired (tokens expire after 1 hour)
3. Token is in correct format: "Bearer <token>"

### Issue: GSI queries not working
**Solution**: Wait 5-10 minutes after deployment for GSIs to backfill
- Check table status: `aws dynamodb describe-table --table-name Rentals`
- GSI status should be "ACTIVE"
